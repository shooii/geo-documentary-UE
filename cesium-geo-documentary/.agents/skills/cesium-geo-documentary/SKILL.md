# Cesium Geo Documentary

Produce videos through a resumable, evidence-backed pipeline. Keep facts, Cesium camera state, narration timing, overlays, and rendering separate.

## Enforce the premium map contract

- Open every standalone region video with a smooth world-to-region descent that finishes quickly: the production cover (about 1.4–1.8 seconds) leads into a deterministic high-altitude globe view (roughly 800–1,200 km over the region center), then one continuous camera flight penetrates a Cesium cloud deck and lands exactly on the parent overview camera. The whole opening—cover plus globe view plus cloud pass-through plus arrival at the boundary overview—must complete in five seconds or less, so keep the descent itself around 2.5–3.5 seconds and cover around 1.4–1.8 seconds. Bake the descent into the same map capture as the boundary reveal; never cut, restart, or crossfade the camera between the cover, the clouds, and the reveal. Use quintic-eased height and pitch profiles, keep longitude/latitude on the region center, pass the cloud deck once, clear the clouds before the overview hold, and prewarm the entire descent path with no-more-than-about-0.5-second reload checkpoints so the sequence never stalls on tiles. Frame the opening so the globe limb, when visible, stays at the upper composition edge; at very high altitude a tiny fraction of limb pixels may dither by 1 LSB between renders and must not block capture stability.
- Make the cloud deck dense and unmistakable. Spread a Cesium `CloudCollection` field of at least two dozen overlapping cumulus clouds across several degrees around the region center. Use varied deterministic widths, aspect ratios, deck altitudes, brightness, and volumetric `slice` values; give every cloud real thickness with tens of kilometers of `maximumSize` z, and use a `noiseDetail` of about 30. Do not use a few oversized `slice: -1` billboard puffs, which read as blurry white dots from space. Ramp cloud alpha from a visible high-altitude bank to full peak at deck crossing, add a brief deterministic soft mist veil only during the actual crossing, then fade both the cloud field and veil completely before the overview hold. The passage must feel like entering, crossing, and exiting one coherent cloud layer without a black flash, persistent haze, or stutter.
- Administrative boundaries are always grounded. Build longitude/latitude positions without altitude, use `clampToGround: true`, terrain-classified fills without polygon height, and normally use a dark-underlay + semantic-main-line pair with adjacent `zIndex` values. If the selected-child underlay obscures its gold main line on a target GPU, hide only that selected underlay and retain the grounded gold main line. Never solve z-fighting with vertical offsets.
- Keep the parent overview fill transparent when a changing terrain-classified fill would rebuild Cesium ground batches or temporarily hide boundary lines. The parent outline carries hierarchy; reserve translucent fill motion for the actively selected child after the introduction.
- Use a clearly distinct but coordinated hierarchy palette: parent boundary clear lake blue `#2D9CDB`, selected child gold `#FFD166`, and context children cool white `#E8F0F5`. Keep context main lines continuously visible after their initial reveal. Never place a black selected underlay above them; hide a selected overlay whenever its alpha is zero and suppress redundant per-frame material writes. The semantic color must remain readable through every handoff, so boundaries never flash black, blank, or white. Treat the parent color as a configurable token, but use `#2D9CDB` as the premium default.
- Preserve every fill entity belonging to the same administrative feature. Cesium splits GeoJSON `MultiPolygon` features into multiple polygon entities, so aggregate fill color properties as an array keyed by the stable feature ID and update every property during selection transitions; never let repeated IDs overwrite earlier polygon parts.
- Reveal the parent with a fast grounded pen-draw: partition outer rings into roughly 56 sequential line segments and move a restrained pen-nib marker along the active segment. Draw once, remove the pen, and settle into a stable parent line; never retrace or float the pen/boundary above terrain.
- Keep the parent camera completely fixed while revealing the parent boundary and child hierarchy.
- Interpolate region travel with `Cesium.EllipsoidGeodesic`, quintic smoother-step position progress, and one continuous low-amplitude height arc. Adapt compact-tour flights to ground distance within about 3.2–5.4 seconds, avoid plateau-and-dive zooms, reserve about 0.9 seconds for arrival settle/hold, and lock the final camera exactly.
- Use Noto Sans SC for map/title/subtitle Chinese, Noto Serif SC for editorial display, Roboto Flex for Latin/numbers, and Roboto Mono for technical labels. Use 8% title tracking without glow.
- Split single-line subtitles by complete spoken phrases rather than raw character counts. Keep numbers with their classifiers and units, including combinations such as `43210人`, `3.2万亩`, `2025年`, and `3952.94亿元`; target a comfortably shorter line than the hard profile maximum and omit terminal or soft punctuation when it does not aid reading. Build a per-topic protected-phrase lexicon from the hierarchical title, parent and child place names, schools, foods, dialects, institutions, and recurring compound terms; use it during every split pass so names and words such as `革命老区`、`水产养殖`、`道路` never break between characters. After automated validation, read the entire cue sequence aloud. If a technically valid split still joins the start of a new phrase to the previous cue, use a validated profile-specific semantic override whose punctuation-normalized text exactly matches the narration.
- Write every concrete number with Arabic digits in canonical narration and visible captions, including years, population, area, distance, production, percentages, money, and counts: use `2024年`、`3.7万人`、`22公里`、`17亿元`, never `二零二四年`、`三点七万人` or other spelled-out measurements. TTS may pronounce those digits naturally, but the canonical text, subtitles, SRT, and VTT must retain Arabic digits.
- Use short, conversational documentary Chinese that a local viewer can understand on first hearing. Prefer concrete subjects and everyday verbs over report language. Reject bureaucratic or production-facing phrases such as `持续推进`、`提质增效`、`赋能`、`构成轮廓`、`可靠边界`、`核验范围`、`不因农场类别省略`、`镜头沿着边界` and `巡游走完`. Internal evidence and coverage limitations belong only in research and QA reports, never in narration or captions.
- Use `zh-CN-YunyangNeural` around `-4%` by default, preserve pronunciation records, normalize formal narration near `-16 LUFS`, and keep music near 0.2. Formal generation must fail instead of silently falling back to Windows SAPI; SAPI is draft-only.
- Keep the connected Figma file, tokens, node map, implementation, and screenshots synchronized. The current design source is `https://www.figma.com/design/3o7fht8p72Aog2YnRzph5n` in `xu yaoting's team`.
- Treat portrait `1080×1920` / `9:16` as the primary social-video profile unless the user requests another master. Frame the parent boundary to occupy roughly 62%–75% of the safe composition without clipping, then use profile-specific child-camera scaling instead of reusing a landscape camera blindly.
- Replace decorative title lines and cartoon mascots with the location-neutral deep-navy and gold cartographer-globe emblem from `design/generated/midnight-globe-emblem.png`. Crop it to a circle at small sizes, keep the fine gold rim readable, and pair it with restrained Chinese serif branding. Keep the visible title in the form `地理乡土情·{hierarchicalTopicName}` with no spaces around the middle dot.
- Keep the identity system and cover template location-neutral. Never hard-code the active topic, country, administrative level, satellite image, or sample locality into reusable component names, defaults, documentation, or asset backgrounds. Use replaceable fields such as `{topicName}`, `{regionPath}`, `{subtitle}`, and `{heroVisual}`; apply real locality content only to instances and production scenes.
- Treat a social-video cover as part of the finished video, not only a sidecar image. Use the location-neutral deep-navy/gold Asia-globe background and cartographer-globe emblem, following the approved reference composition: `地理乡土情` at upper left, one large hierarchical Chinese topic title in the lower framed panel, the Chinese subtitle, and `地理 · 人文 · 时代`. Never show a hierarchy-path chip, English copy, issue codes, aspect-ratio badges, or `PORTRAIT / 9:16` on the cover. Export the production cover as PNG, normally show it for about 1.2–1.6 seconds, and shorten it when needed so the cover, high-altitude globe, cloud pass, and first visible boundary-introduction stroke all occur within five seconds. Offset the map, narration, music, photos, captions, SRT, and VTT by the same duration.

## Run the workflow

### Match the latest approved town-film expression

When the user names an existing town video as the expression reference, locate the newest validated portrait output for that reference region by final-video modification time and inspect its current region content, cover, composition metadata, captions, visual manifest, and QA report. Reuse its presentation grammar only: the `地理乡土情·{县}{镇}` identity, 1.4–1.8 second embedded cover, continuous world/cloud/parent descent, map-first clean program, cue-bound verified-real evidence cards, persistent visited village boundaries and names, silent return, conversational closing, and portrait delivery settings. Never copy the reference town's facts, imagery, village order, timing seconds, or tourism claims into the target town.

Before regenerating a legacy town, migrate the target content source completely:

- Set `title` and the cover output path to `地理乡土情·{县}{镇}` and keep the named MP4/SRT/VTT/cover/publishing deliverables aligned.
- Convert every concrete number in narration and protected phrases to Arabic digits before voice generation.
- Remove production-language endings such as `巡游走完`、`视角回到`、`镜头回到`; keep the return silent and make any closing line an observation about the locality.
- Recalculate `tourIntroSentences` from the actual provider sentence cues that occur before the first toured child. A newly inserted full stop can change cue count; verify `intro cue count + tour child count + optional outro cue` before calling `voice`.
- Treat every existing profile-specific subtitle override as invalid after narration semantics or provider cue boundaries change. Delete it or rebuild it so each override's punctuation-normalized chunks exactly equal the new spoken cue.
- Ensure `content/publishing/<region>.json` exists before running the publishing validator; it validates and exports copy but does not author a missing source file.
- Run `compose` to rebuild the standalone composition and sidecar captions, then run `scripts/render-profile.ps1 -Profile portrait -Quality high -Regions <id>` to produce the final MP4. `compose` alone does not render the high-quality video.
- Run final QA against the newly rendered ID-named MP4, then create the human-readable Chinese-titled MP4 copy only after QA passes.

2. Lock the active topic and output namespace. If the user switches region or level, stop all old-topic research and rendering immediately. Reuse only generic technical assets, and never overwrite a historical final video with the new topic.
3. Resolve the topic's geographic role and immediate-child level before research. Support `world → continent → country → admin1 → admin2 → admin3/locality → township/subdistrict → administrative village/community → natural village/settlement or rural area`. Preserve the complete reliable boundary set: retain statutory children, forest farms, enclaves, islands, and every other verified management unit in `boundaryUnitIds` so no unit is dropped merely because it is a farm, forest farm, or special management area. 4. Establish boundary evidence before normalization. Prefer official GIS/WFS/GeoJSON/SHP, then credible public administrative data. Accept ESRI Shapefile only as a complete set with `.shp`, `.shx`, `.dbf`, and `.prj`; read `.cpg` when present, record every sidecar, detect the source CRS, reproject to EPSG:4326, preserve the originals, and fail on unresolved DBF encoding or private-use characters. Never simplify adjacent administrative polygons independently. Never use Voronoi, hand-drawn partitions, or center-point approximations as administrative boundaries.
5. Validate and normalize parent boundaries, child boundaries, and any narrated rivers, lakes, bays, mountains, ridges, coastlines, islands, roads, or settlements before scripting. Every applicable script should cover area, location and physical setting, population with year and population type, economy or livelihoods with year, historical sequence, representative culture, local customs, language/dialect, characteristic food or produce, ecology, and contemporary development. For township/subdistrict topics, also research notable local middle schools or equivalent secondary schools; include a school only when its identity, locality, significance, and a real exact campus image or confirmed graduating-cohort photograph are verified. School inspections, meetings, classroom lectures by visiting officials, award ceremonies, teacher-day visits, office scenes, and generic activity groups do not qualify as school-life evidence and must not appear. Distinguish town-specific facts from county or regional cultural context. Adapt fields at very small rural scales instead of inventing unavailable GDP or population data.

Evoke familiarity through verified concrete local textures—roads, shorelines or fields, market rhythms, dialect sounds, seasonal work, kitchens, and exact foods—without inventing stock details such as school bells or a daily commute. Reject government-work imagery even when it is official: meetings, training sessions, inspections, research visits, briefings, signing ceremonies, office scenes, posed official groups, banners, and lecture rooms are not documentary substitutes for agriculture, food, fishing, culture, villages, schools, or daily life. Do not label children in the overview.

After the final child, return to the parent camera while retaining every visited boundary and label. Add `narrationStartSeconds` exactly once, then add the cover offset exactly once in composition. ## Use the bundled scripts

Run scripts from the project root. Prefer the CLI wrapper when it covers the task.

```powershell
pnpm geo-video doctor
python .agents/skills/cesium-geo-documentary/scripts/import-shapefile.py data/raw/example.shp --region-id <id> --region-name <name> --parent-id <parent-id> --id-field <id-field> --name-field <name-field> --expected-children <count>
pnpm geo-video validate-data --region <region-id>
pnpm geo-video capture --region <region-id> --profile landscape --encode
pnpm geo-video compose --region <region-id> --profile landscape
pnpm geo-video qa --region <region-id> --profile landscape --stage final
pnpm geo-video master --regions <id-1,id-2,...> --profile landscape --output renders/final/master.mp4
pnpm typecheck
pnpm test
```

Key deterministic scripts:

- `import-shapefile.py`: ingest a complete polygon SHP set, decode DBF attributes, detect and transform the source CRS, write parent/child GeoJSON, and emit a QA report and coverage manifest.
- `preprocess-boundaries.py` and `validate-geodata.py`: normalize and validate GeoJSON data.
- `restructure-child-units.py`: apply a reviewed merge/rename/split plan (`config/child-unit-restructures/<region>.json`) to a region's direct children. It rewrites `children.geojson`, the region file, and the coverage manifest, re-deriving each unit's label point and camera from the new parcel, and prints the parent gap/overlap area so a merge or split that tears the parent can be spotted. Unlike `import-shapefile.py` it is driven by an explicit plan, which is what makes a boundary correction reviewable and reproducible; always `--dry-run` first. A plan carrying a `status` other than `active` is a record, not instructions, and the script refuses to run it — prefer correcting the source data and re-importing when the user wants the dataset itself fixed (then the plan file documents *why*, and the merges become a fact of the data rather than a layer applied on top of it).

  ⚠️ Pushing the same correction into a live project: a rename or a split must **create** the scene, never mutate it. `GET /api/projects/:id` runs `normalizeProject`, and a schema-v2 scene list counts as the editor's explicit selection (`preservesDeletedScenes`), so the moment the region stops carrying an old id the *first GET* already drops that scene. A patch that then "renames" the dropped scene is a silent no-op, and the new canonical scene gets dropped too because no saved scene claims it — the change looks applied but the scene is simply gone. Read the pre-restructure revision **from disk** (the stored `workspace/projects/<id>.vNNNNNN.json` still has it; the API view no longer does) to recover its narration and placements, then send one PUT whose payload already contains a scene with the new id. The same trap silently skips "move the photos of the merged-away village onto its host" branches, so re-scope the assets **and** rebuild the placements.

  ⚠️ Re-importing a region whose units were renamed: `import-shapefile.py` derives `tourChildIds` by intersecting the *saved* order with the new boundary ids, so a unit whose id changed upstream matched nothing and vanished from the tour while staying a boundary unit (那澳村 became a boundary unit that no scene ever visited). Fixed by appending boundary units the saved order does not mention; still, after a re-import check `tourChildIds.length == boundaryUnitIds.length` and that `content/regions.zh-CN.json`'s narration and `tourOrder` were rebuilt for the new count, since the import does not touch the content entry (that is `town-bootstrap.ts`'s `writeGeneratedContent`, and only when creating a plan).

  ⚠️ The operator edited the source SHP: re-import the town they edited, and only that town. ## Recover from failures

- Preserve successful stages and rerun only the failed region/profile.
- `生成或复用正式配音 exited with 1` with `WSServerHandshakeError: 403, message='Invalid response status'` is not a clock, token or voice problem: since October 2026 Microsoft answers the synthesis websocket on the legacy host `speech.platform.bing.com` with 403, and Edge 155 synthesizes through `api.msedgeservices.com/tts/cognitiveservices/websocket/v1` instead (the voice list still answers on the legacy host, which is why `--list-voices` keeps working and makes the failure look like a credential issue). `edge-tts==7.2.8` still points at the legacy host, so run `python scripts/patch-edge-tts.py` — it repoints `WSS_URL` and makes the DRM `Date` parsing locale-independent, is idempotent (`--check` and `--version <edge build>` available), and has to be re-run after any `pip install --target .python-packages` because that directory is gitignored. Verify with the exact command from the job log (`python -m edge_tts --voice <voice> --rate=<rate> --file <input.txt> --write-media <source.mp3> --write-subtitles <src.srt>`); a real 1,275-character narration takes ~16 s and writes a ~1.6 MB mp3.
- A re-imported boundary that still looks like the old one in the preview is a browser-cache symptom, not a data symptom: check `data/regions/<id>.json` on disk first, then confirm the player reports a `dataVersion` in `/runtime-config.json` and that the page requests `/data/**?v=<dataVersion>`. `/data/**` must be served `no-cache` with an ETag — never `immutable`.
- Data that exists on disk but not in the Studio is a process-memory symptom. Both long-lived scans are keyed on a directory signature for exactly this reason (`getAdminCatalog` on the boundary source root, `listProjects` on the revision files' name/size/mtime), so an edit or a git checkout no longer needs a restart. If something is still invisible, compare the signature helpers before blaming the files.
- Scene lengths that trail the narration are a round-trip symptom, not a data symptom: the authoritative duration only arrives with the next render spec (autosave debounce + PUT + rebuild). The strip is expected to show a draft estimate immediately (`draftSceneDuration()` → `max(2, 字数 / 4.1)`, mirroring `estimatedProjectCues`), and the spec then replaces it. If a clip lags the cursor, or a clip grows while 总时长 stands still, run `verify-scene-strip-width.mjs`.
- Keep missing tokens, unavailable services, rejected generated images, TTS fallback, capture timeouts, and data gaps in external diagnostics and manifests. Never narrate pipeline limitations, missing boundaries, unavailable touring, AI generation, or implementation failure to the audience; rewrite the editorial route naturally around verified material.
- Save diagnostics before aborting a failed frame or render.
- If Cesium Ion is unavailable, use an explicitly documented offline imagery/ellipsoid fallback; never claim terrain was rendered when it was not.
- If a formal satellite provider is unavailable, stop formal capture and preserve diagnostics. Do not silently fall back to Natural Earth, OpenStreetMap, a blurred screenshot, or generated imagery.
- If exact administrative boundaries cannot be acquired or registered reliably, stop the formal video. Do not substitute Voronoi cells, center-point partitions, hand-drawn lines, or visually plausible approximations.
- If only terrain is unavailable, keep the licensed satellite layer, use the ellipsoid, and disclose that real terrain was not rendered.
- If Figma is unavailable, deliver tokens, component specifications, node-map placeholders, and an import plan, but still render the required location-neutral production cover from the synchronized code/tokens and embed it in the final video.
- If ImageGen fails or clean-broadcast mode is active, use the planned verified real photo or a map-led scene. Never replace a required exact culture/history subject with a generic local image. Record locality, subject, resolution, license, and attribution in the external photo manifest.
- If formal premium TTS fails, stop the release build and preserve diagnostics. Windows SAPI may be used only with an explicit draft flag; record it as non-release-ready and regenerate all dependent timing before final delivery.
